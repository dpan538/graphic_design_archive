## Purpose

## IMG00-IMG04 Handling

The generated records follow the corrected image-presence model:

- `IMG00`: image frame exists, but no source image is displayed.
- `IMG01`: controlled thumbnail state.
- `IMG02`: source-hosted viewer/embed state; no local copy.
- `IMG03`: open/reusable image state, still requiring source credit and any protocol review.
- `IMG04`: no image frame; pure text/authority/event/appendix page.

Image code does not define physical image size. Size remains a template/layout decision.

## Draft Limitations

These JSON files are candidate records only.

They intentionally preserve uncertainty:

- source metadata is prefilled from target-selection rows, not yet copied from the source page field by field;
- historical classifications are inherited from first-ingest scope cells;
- rights states are conservative draft states;
- `IMG03` draft rows still disable local copying until item-level review is complete;
- relationships are empty until source metadata and authority reconciliation are reviewed.

## Next Workflow Step

The next mechanical step should be source-level metadata capture:

1. open each canonical URL or approved source page;
2. capture raw source fields exactly as displayed;
3. add field provenance per captured field;
4. confirm or downgrade rights/image presence state;
5. record exact citation and access evidence;
6. only then promote candidate drafts toward `source_reviewed` or `rights_reviewed`.

This preserves the archive principle: index first, verify field provenance, then classify and publish.
