# Zero-object exposure policy

Exploration frontend object count, title count, thumbnail count, card count, link count, and object-ID count are all zero. No public Exploration frontend or route exists in this round.

Every domain contract uses positive exact-key validation. The recursive boundary rejects archive identity keys and project record DTO shapes; Node IDs and references must use conceptual prefixes. Positive validation prevents archive data from hiding under arbitrary metadata fields.

Object titles, thumbnails, URLs, cards, identifiers, routes, DTO imports, related-record language, and similar-work language are rejected from active Exploration implementation. RenderedPng has a closed safe metadata schema. Container local edits have typed scalar values rather than arbitrary nested payloads.

The guard is scoped to Exploration implementation and dependencies. It does not scan or change ordinary Search behavior.
