# Badge System Rules

These badges are special digital archive assets. They may appear as file marks,
collection seals, appendix markers, source-return marks, export stickers, or
project ephemera. They are not folder-color dots and should not replace folder
membership badges.

## Sets

This selected badge release contains two groups of eight:

| Group | Count | Language / symbol field | Purpose |
|---|---:|---|---|
| B01 | 8 | English | Core archive-control labels. |
| B02 | 8 | Japanese / Devanagari / Spanish / symbols | Cross-script special-file marks. |

No additional script groups should be introduced unless a future release brief
explicitly asks for them.

## Design Constraints

- Use real words, characters, or symbols. Do not invent pseudo-script forms.
- Keep each badge symbolic enough to survive at small sizes.
- Prefer one field color plus paper/ink; use two accent colors only when the
  badge needs a deliberate contrast.
- Use geometry as structure, but do not let the shape cut into the content.
  Badge bodies, frames, text, and pins must be separate layers.
- Every badge in a release needs a distinct silhouette and proportion. If two
  badges read as visually similar at thumbnail size, redesign one of them.
- Each specimen badge must carry four information layers: code, primary label,
  function note, and usage/detail line.
- Avoid gradients, mascots, pictorial illustration, and decorative clutter.
- Text must remain readable at the specimen size and recognizable at icon size.
- Multilingual badges must preserve the script's normal writing behavior; do
  not distort scripts into ornamental texture.
- Symbol-only badges must still carry a functional meaning in metadata:
  annotation, relation, review, return, appendix, or source.

## Placement Rules

- Badges are rare digital assets, not default UI chips.
- Use them on special files, appendix covers, export sheets, collection packets,
  and project merchandise/specimen views.
- Do not use more than three symbolic badges in one record view.
- Do not mix these badges with folder color dots unless the visual hierarchy is
  explicit: symbolic badge first, folder dots second.
- If a badge could be mistaken for an institutional logo, add nearby context or
  use a more neutral shape.
